# ALS 面部微动作 AAC 输入原型

本项目是一个本地运行的 ALS 面部微动作 AAC 输入原型，优先使用 MacBook 内置摄像头。目标不是识别尽可能多的表情，而是验证患者仍能稳定、低疲劳、低误触完成的少数面部微动作，并把这些动作作为 AAC 输入信号，用于触发预设短语、确认/取消、休息表达和后续扫描选择。

本系统不把任何单一面部动作直接等同于患者真实意图。所有动作都先被视为输入信号，只有在个人校准、稳定性测试和照护者确认后，才映射为具体短语或操作提示。

模型和 wasm 文件已放在 `public/mediapipe/`，运行时不需要再从 Google Storage 或 CDN 拉取核心检测资源。

## 当前定位

```text
摄像头
→ FaceLandmarker 关键点 / blendshape / 头部信号
→ 面部信号与可选动作
→ 动作事件
→ 动作含义配置
→ 文字显示 + 可控 TTS 播报
```

当前版本优先验证：

- 眨眼短码是否可靠。
- 单次短眨是否会被自然眨眼误触。
- 长闭眼是否会被疲劳闭眼误触。
- 抬眉、张嘴、摇头、微笑是否能作为可选输入通道。
- 动作含义配置是否能统一驱动屏幕文字、TTS 和动作说明。
- TTS 是否只在明确短语或确认后播报。

## v0.3 当前设计

- 眨眼短码是当前主输入通道。
- 不实现完整摩尔斯字母输入，只使用 2-3 个符号映射少量高频短语。
- 单次短眨默认无指令，静默忽略。
- 单次长闭眼默认无全局指令，只在确认场景中表示取消。
- 超过 3 个符号的短码直接忽略，避免把过长输入截断成有效短码。
- 抬眉、张嘴、摇头、微笑默认关闭；完成引导校准并手动开启后才执行对应动作映射。
- 引导校准完成前，短码和可选动作只显示和记录，不执行短语播报或确认流程。
- 动作检测和动作含义已经分离，屏幕文字、语音播报和动作说明都读取默认动作配置。
- 高级设置允许照护者为每个动作修改一条“表达文字”，屏幕显示和语音播报使用同一句，并保存到本机；不提供关闭显示或关闭播报。
- 挠痒痒和调整体位已加入二级选择：先表达大类，再自动轮流高亮具体位置/方式。
- TTS 默认先取消上一条语音队列，避免误触短语排队播放。
- 清空按钮会同时停止当前播报。
- 面部描边可视化：眼睛、眉毛、嘴唇、脸部轮廓和中心线用于调试观察。
- 摄像头画面使用完整显示，不再为了填满区域自动裁切放大；检测到人脸尺度突变时，会短暂等待画面稳定，避免可选动作误触。
- 引导校准：采集自然睁眼/闭眼 EAR，自动更新眨眼阈值，并记录短眨、长闭眼样本；核心校准完成后即可点击“完成确认”。
- 同一患者完成确认后，校准档案会保存在当前电脑/浏览器本地，下次打开会自动沿用；更换患者或状态变化明显时再点“重置”重新校准。
- 普通界面默认隐藏事件日志和测试记录；工程测试模式可查看最近事件、单独验证短码、记录动作识别/文字显示/语音开始延迟，并导出 JSON/CSV 供工程复盘。

## 默认眨眼短码

操作口径：

- 短眨眼：闭眼后马上睁开，约 `0.1-0.5 秒`。
- 长闭眼：闭眼约 `1 秒`，有效范围约 `0.7-2.8 秒`，最后必须睁开，系统在睁开后识别。
- `短眨 + 长闭眼`：先短眨并睁开，然后在约 `2.5 秒` 内开始长闭眼，长闭眼后再睁开。

| 编码 | 动作 | 默认解释 | 是否播报 | 备注 |
| --- | --- | --- | --- | --- |
| `.` | 单次短眨 | 无指令 | 否 | 防止自然眨眼误触 |
| `-` | 单次长闭眼 | 单独不播报；确认场景中取消；校准后可作为休息 1/2 | 否 | 不做全局“否” |
| `..` | 两次短眨 | 我需要帮助，请过来一下 | 校准后是 | 校准前只记录 |
| `...` | 三次短眨 | 紧急求助，请马上查看 | 校准后是 | 校准前只记录 |
| `--` | 两次长闭眼 | 我想休息 | 校准后是 | 两次可在 6 秒内分开完成，不自动暂停识别 |
| `.-` | 短眨 + 长闭眼 | 我想挠痒痒 | 校准后是 | 进入挠痒痒二级选择 |
| `-.` | 长闭眼 + 短眨 | 我想调整体位 | 校准后是 | 进入调整体位二级选择 |

引导校准完成前，系统不会把短码直接当作患者意图执行。短码测试只在工程测试模式中显示，只判断“收到的短码是否匹配”，不会触发真实短语或 TTS。

## 二级选择

进入二级选择后，系统会自动轮流高亮选项。患者可以：

- 两次短眨：选择当前高亮项。
- 单次长闭眼：取消二级选择。
- 抬眉：如果已开启，可轻抬眉后放松，选择当前高亮项。
- 摇头：如果已开启，可取消。

挠痒痒选项：头部、脸部/耳边、背部、手臂、腿部、请查看。

调整体位选项：向左侧翻身、向右侧翻身、抬高上身、放低上身、调整枕头、调整腿脚。

## 可选动作

| 动作 | 默认状态 | 当前用途 | 风险 |
| --- | --- | --- | --- |
| 抬眉 | 关闭 | 播报“是，确认”；有待确认事项时优先作为确认 | 可能被表情牵连 |
| 张嘴两次 | 关闭 | 播报“我需要吸痰，请马上查看” | 延髓受累时可能非主动，必须先测试 |
| 摇头 | 关闭 | 播报“否，不是，取消”；在确认窗口内取消 | 颈部疲劳、画面位移误判 |
| 微笑 | 关闭 | 播报“谢谢，可以，我还好” | 不适合紧急或护理指令 |
| 微笑两次 | 关闭 | 播报“我爱你” | 情感表达，必须先放松再第二次微笑 |

这些动作必须手动开启，并且只有完成引导校准后才触发 TTS。校准前仍只显示和记录，不播报。
当前可选动作已按低疲劳测试收紧：抬眉轻抬约 `0.25 秒` 后放松，检测到上下点头或画面上下位移时会临时暂停抬眉判断；张嘴只需微张约 `0.2 秒` 后闭合，`6 秒` 内重复两次；张嘴信号出现时会临时抑制抬眉，只有明显张嘴才会抑制微笑；微笑使用嘴角横向距离相对个人基线的增长量，轻微闭嘴微笑约 `0.25 秒` 后放松；微笑两次必须中间完全放松约 `0.5 秒`；摇头在 `4 秒` 内极轻微左右变化即可。

普通界面的“当前动作说明”只显示当前启用的动作。只启用眨眼时不显示抬眉、张嘴、摇头或微笑说明；勾选可选动作后才追加对应说明。工程测试记录只在工程模式中显示。

## 下一步

建议优先顺序：

1. 用工程测试面板做单一患者短时测试：导出 JSON/CSV，复盘正确率、文字延迟、TTS 延迟和误触场景。
2. 根据记录微调眨眼阈值、闭眼帧数和短码节奏。
3. 用高级设置试改 2-3 个动作含义，验证保存、恢复默认、导出和导入是否符合照护者习惯。
4. 扩展个人校准：加入可选动作基线和信号质量门控。
5. 再决定哪些护理动作需要确认流程。
6. 扩展扫描选择模式：患者用一个稳定动作选择高频短语。

## 运行

### 桌面应用

开发者在 macOS 上生成可发给其他人的安装包：

```bash
npm install
npm run dist:mac
```

生成结果在 `release/` 目录中，优先分发 `.dmg`。对方安装后双击打开，首次使用时允许摄像头权限即可。

本机快速试运行桌面版：

```bash
npm run desktop
```

说明：

- 桌面版会把 `dist/` 页面、MediaPipe 模型和 wasm 一起打包，不需要对方安装 Node 或启动 Vite。
- 未签名的 macOS 包在部分电脑上可能需要右键选择“打开”，或在“系统设置 > 隐私与安全性”中允许打开。

### 开发模式

```bash
npm install
npm run dev
```

打开 Vite 输出的本地地址后，点击「启动」并允许摄像头权限。

如果在 Codex 的 in-app browser 里看到“摄像头权限被拒绝”，请用系统浏览器打开同一个地址：

```text
http://127.0.0.1:5173/
```

macOS 仍然拒绝时，检查「系统设置 > 隐私与安全性 > 相机」，给 Chrome、Safari 或当前浏览器开启权限。

## 调参

- 眨眼阈值：EAR 低于该值时判为闭眼。
- 闭眼帧数：连续低于阈值的最小帧数，用于减少误判。
- 摄像头：授权后会自动优先选择 MacBook/FaceTime/Built-in 标签的设备，也可以手动切换。
- 外接摄像头：插入或拔出后，下拉框会自动刷新；若已启动检测，切换下拉框会用新摄像头重启检测。

## 工程测试

工程测试默认不在普通前端界面显示。工程师访问地址后加 `?debug=1` 可打开“工程测试”折叠区：

```text
http://127.0.0.1:5173/?debug=1
```

工程测试用于短码验证和结构化记录，不等同于医疗记录。建议每次测试前先选择“预期动作”，点击“开始记录”，逐个动作测试后可手动标记上一条“正确/错误”，最后导出 JSON 或 CSV。

记录内容包括：

- 动作类型、短码、预期动作、识别结果和人工正确/错误标记。
- 动作持续时间、从动作结束到识别的延迟、从动作结束到文字显示的延迟。
- TTS 排队时间和实际开始播报时间；部分浏览器如果不触发语音开始事件，则只记录排队时间。
- FPS、EAR、抬眉/张嘴/微笑/摇头信号和是否检测到人脸。
