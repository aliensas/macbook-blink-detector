# v0.4 Action Config 与高级设置

## 1. 目标

v0.4 只做一件事：让照护者为每个已识别动作自定义表达含义，并保存到当前 Mac 浏览器本机。

```text
动作识别结果
→ action-config
→ 屏幕显示文字
→ 语音播报文字
```

本阶段不修改底层动作识别阈值，不新增复杂菜单，不做跨设备同步。

## 2. 核心规则

1. 每个动作触发后必须有屏幕显示。
2. 每个动作触发后必须有语音播报。
3. 高级设置只能修改表达含义，不能关闭显示，不能关闭播报。
4. 高级设置不允许普通用户修改 EAR、blendshape、头部姿态、动作窗口等检测参数。
5. 所有默认含义必须可以一键恢复。

## 3. 配置结构

```js
{
  id: "smile_double_love",
  gestureId: "smile_double",
  label: "微笑2次",
  displayText: "我爱你",
  speechText: "我爱你",
  category: "emotion",
  locked: false,
  editable: {
    displayText: true,
    speechText: true
  }
}
```

## 4. 字段说明

| 字段 | 含义 | v0.4 是否可编辑 |
| --- | --- | --- |
| `id` | 配置 ID | 否 |
| `gestureId` | 检测层动作 ID | 否 |
| `label` | 动作名称，如“微笑2次” | 否 |
| `displayText` | 屏幕显示文字 | 是 |
| `speechText` | 语音播报文字 | 是 |
| `category` | 分类，如 `care` / `emotion` / `control` | 否 |
| `locked` | 是否保护默认项 | 否 |
| `editable` | 高级设置可编辑字段 | 否 |

v0.4 不提供这些字段给用户设置：

```text
enabled
speak
requiresConfirmation
threshold
duration
cooldown
```

## 5. 默认动作含义

| 动作 | 默认显示 / 播报 |
| --- | --- |
| 短眨2次 | 我需要帮助，请过来一下 |
| 短眨3次 | 紧急求助，请马上查看 |
| 长闭眼2次 | 我想休息 |
| 短眨 + 长闭眼 | 我想挠痒痒 |
| 长闭眼 + 短眨 | 我想调整体位 |
| 抬眉 | 是，确认 |
| 张嘴2次 | 我需要吸痰，请马上查看 |
| 摇头 | 否，不是，取消 |
| 微笑 | 谢谢，可以，我还好 |
| 微笑2次 | 我爱你 |

## 6. 高级设置界面

每个动作一行：

```text
动作名称
屏幕显示输入框
语音播报输入框
测试播报
恢复默认
```

不显示“关闭播报”“只显示不播报”“禁用动作”等开关。

## 7. 本地保存

使用 localStorage 保存用户改过的文字：

```text
alsFacialAac.actionConfig.v2
```

保存格式只包含用户自定义字段：

```js
{
  "smile_double_love": {
    "displayText": "我爱你们",
    "speechText": "我爱你们"
  }
}
```

启动合并顺序：

```text
代码默认配置
→ 本机保存的自定义文字
→ 当前运行状态
```

## 8. 导出 / 导入

导出内容只包含自定义文字，不包含摄像头、阈值、模型或患者隐私记录。

导入时必须校验：

- `id` 必须存在于默认配置中。
- `displayText` 和 `speechText` 必须是非空文本。
- 未识别字段直接忽略。
- 导入后立即刷新动作说明。

## 9. 本阶段不做

- 不做扫描选择模式。
- 不做护理菜单。
- 不做多患者档案。
- 不做云同步。
- 不让用户关闭显示或语音播报。
- 不让用户修改动作识别参数。

## 10. 当前实现状态

已实现：

- 高级设置面板。
- 每个动作的屏幕显示文字和语音播报文字输入框。
- 保存到本机 `localStorage`。
- 取消未保存修改。
- 单项恢复默认。
- 全部恢复默认。
- 导出 JSON。
- 导入 JSON 并保存。
- 测试播报。

仍需真实使用测试：

- 照护者是否能理解“保存 / 取消修改 / 恢复默认”的区别。
- 自定义长文本是否会让普通界面换行过多。
- 导入/导出配置在另一台 Mac 上是否符合预期。
