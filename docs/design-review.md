# ALS 面部微动作 AAC 输入原型：设计审核稿

## 1. 项目定位

本项目不是“多表情识别器”，而是“患者个人化的低疲劳面部开关输入器”。

目标是用 MacBook 摄像头在本地识别患者仍能稳定、低疲劳、低误触完成的少数面部微动作，将这些动作作为 AAC 输入信号，用于触发预设短语、确认/取消、休息模式，以及后续扫描选择。

核心原则：

```text
动作不是意图。
动作只是输入信号。
只有经过个人校准、稳定性测试和照护者确认后，动作才映射为具体短语。
```

## 2. 当前系统流程

```text
MacBook 摄像头
→ MediaPipe FaceLandmarker
→ 眼部 EAR / blendshape / 头部左右信号
→ 眨眼短码与可选动作
→ 确认流程
→ 屏幕文字 + 可控 TTS 播报
→ 工程测试 JSON/CSV 导出
```

当前重点不是增加动作数量，而是降低误触、疲劳和误解风险。
界面中的“面部描边”只用于观察眼睛、眉毛、嘴唇、脸部轮廓和中心线是否稳定，不直接参与患者意图解释。
引导校准完成前，系统只记录短码，不执行短语播报或确认流程。

## 3. 默认启用内容

默认启用：

- 眨眼短码。
- 文字输出。
- 浏览器本地 TTS。
- 休息模式。
- 最近事件日志。
- 工程测试面板，用于评估动作识别正确率、文字响应延迟和语音响应延迟；普通前端默认不显示。

默认关闭，需要完成引导校准并手动开启：

- 抬眉确认。
- 张嘴吸痰。
- 摇头取消。
- 微笑表达。

校准前，这些动作只显示和记录，不播报。校准后，只有手动开启的动作才执行对应语义映射。

## 4. 眨眼短码设计

本系统不实现完整摩尔斯字母输入。当前只使用 2-3 个眨眼符号构成少量高频短语。
超过 3 个符号的短码会被直接忽略，避免把过长输入截断成有效短码。

| 短码 | 动作 | 当前含义 | 播报 |
| --- | --- | --- | --- |
| `.` | 单次短眨 | 无指令 | 否 |
| `-` | 单次长闭眼 | 单独不播报；确认场景中取消；校准后可作为休息 1/2 | 否 |
| `..` | 两次短眨 | 我需要喝水或润口 | 校准后是 |
| `...` | 三次短眨 | 紧急求助，请马上查看 | 校准后是 |
| `--` | 两次长闭眼 | 我想休息，暂停识别 5 分钟 | 校准后是；两次可在 6 秒内分开完成 |
| `.-` | 短眨 + 长闭眼 | 进入口腔护理确认 | 校准后只播报确认提示 |
| `-.` | 长闭眼 + 短眨 | 进入体位调整确认 | 校准后只播报确认提示 |

单次短眨不作为“是”，因为自然眨眼误触风险太高。
短码测试只在工程测试模式中显示，只验证输入是否匹配，不执行真实短语、TTS 或休息暂停。为了降低患者负担，核心校准完成后即可确认。

## 5. 确认流程

护理类和体位类短码不直接播报最终指令。

口腔护理流程：

```text
短眨 + 长闭眼
→ 系统提示：检测到可能需要口腔护理。连续两次短眨确认，长闭眼取消。
→ 连续两次短眨确认：我可能有口腔不适，请查看是否需要润口、清理口腔或吸痰。
→ 单次短眨：忽略，不确认。
→ 长闭眼取消：已取消。
```

体位调整流程：

```text
长闭眼 + 短眨
→ 系统提示：检测到可能需要调整体位。连续两次短眨确认，长闭眼取消。
→ 连续两次短眨确认：请帮我检查并调整体位。
→ 单次短眨：忽略，不确认。
→ 长闭眼取消：已取消。
```

确认窗口固定为 10 秒。超时后自动取消，单次短眨和无效短码不会延长确认时间。确认状态优先于直接短语，确认窗口内的两次短眨表示确认，不表示喝水/润口。

## 6. 可选动作设计

| 动作 | 默认状态 | 当前用途 | 主要风险 |
| --- | --- | --- | --- |
| 抬眉 | 关闭 | 确认；确认窗口内可确认护理/体位提示 | 可能被表情或疲劳牵连 |
| 张嘴两次 | 关闭 | 播报“我需要吸痰，请马上查看” | 延髓受累时可能非主动，必须先测试 |
| 摇头 | 关闭 | 否/不是/取消；确认窗口内取消 | 颈部疲劳、画面位移误判 |
| 微笑 | 关闭 | 谢谢/可以/我还好 | 不适合紧急或护理指令 |

建议审核重点：

- 患者能否稳定完成该动作。
- 完成后是否明显疲劳。
- 是否容易被自然表情、呼吸、流涎、疼痛、姿势变化误触。
- 照护者是否能接受该动作进入通信映射。

## 7. TTS 安全设计

TTS 是对外表达患者意图的出口，因此默认更保守：

- 单次短眨不播报。
- 单次长闭眼不播报。
- 可选动作默认关闭，校准前不播报。
- 引导校准完成前，任何短码不播报。
- 护理/体位短码确认后才播报最终短语。
- 每次播报前取消上一条语音队列，避免误触短语连续排队。
- 提供“重播”“清空并停止播报”“暂停”按钮；关闭语音开关会立即停止当前播报。

## 8. 当前待验证问题

工程验证：

- MacBook 摄像头权限和设备选择是否稳定。
- FaceLandmarker 在不同光线下是否稳定。
- EAR 阈值和闭眼帧数是否需要个人校准。
- 眨眼短码是否会被自然眨眼误触。
- TTS 是否在目标浏览器中可用。
- 工程测试导出的 JSON/CSV 是否足以定位误触、漏识别、文字延迟和 TTS 延迟。

患者/照护者验证：

- 单次短眨是否过于容易误触。
- 两次短眨是否能稳定表达“喝水/润口”。
- 三次短眨作为紧急求助是否负担过高。
- 两次长闭眼作为休息模式是否可能与疲劳闭眼混淆。
- 口腔护理和体位调整是否必须保留二次确认。
- 哪些可选动作应该启用，哪些必须保持关闭。

```text
可靠眨眼短码 + 确认流程 + TTS + 休息模式 + 可选动作映射 + 工程测试记录
```

v0.2.1 建议：

- 根据记录调整阈值、节奏和确认窗口。
- 信号质量门控。
- 更完整的个人校准流程。

- 患者个人动作档案。
