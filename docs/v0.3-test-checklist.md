# v0.3 Mac 本地测试清单

本清单只用于当前 Mac 本地版测试。旧版规则已删除；历史内容如需恢复，请从 GitHub 回滚。

## 测试前确认

- 打开 `http://127.0.0.1:5173/`。
- 右侧“当前动作说明”应显示当前规则。
- 点击“启动”，允许摄像头权限。
- 点击“启动”后，摄像头必须稳定保持“检测中”至少 5-10 秒；如果画面闪一下变黑或出现“检测失败”，必须先查浏览器控制台，不继续测试动作。
- 修改检测循环、头部运动保护、抬眉/微笑/眨眼相关函数后，必须确认控制台没有 `ReferenceError`、`TypeError` 或“检测循环出现错误”。历史故障见 `docs/runtime-regression-notes.md`。
- 完成引导校准并点击“完成确认”。
- 每个动作最多连续测试 3 次；患者疲劳时立即停止。
- 长闭眼按“闭眼约 1 秒后睁开”测试；有效范围约 `0.7-2.8 秒`，系统在睁开后识别。
- 眨眼短码必须连续：短眨后约 `1.2 秒` 内开始下一次动作，长闭眼后约 `1.6 秒` 内开始下一次动作；间隔过长应静默清空，不触发指令。
- `短眨 + 长闭眼` 按“短眨并睁开 -> 1.2 秒内长闭眼约 1 秒 -> 睁开”测试。
- 闭眼 `3 秒以上、不足 8 秒` 应全局回到“等待输入”：二级菜单、确认窗口、输入管理中退出当前流程；普通等待输入状态下清空未完成短码，并明确显示“等待输入”。
- 闭眼 `8 秒以上` 即使未睁开也应进入系统安静模式；安静模式中连续短眨 4 次恢复文字和语音播报；连续 3 次短眨后若第 4 次未在窗口内出现，应触发紧急求助；恢复后的约 `0.9 秒` 内，第 5 次短眨不应进入新短码。
- 直接播报类动作触发后，系统应保留上一句输出，但状态回到等待输入；约 `2 秒` 内普通眨眼或可选动作不应触发新指令，但严格三短眨紧急求助应能打断冷却。
- 二级菜单类动作触发后应进入对应轮询菜单，不应立即回到等待输入；第一次短眨应锁定当前高亮项，第二次短眨选择锁定项。
- “人脸质量门控”默认开启；测试动作前先看人脸质量状态，质量不足但眼睛仍可用时应保留眨眼短码，并暂停可选面部动作。
- “人脸近景框”默认开启；它只用于观察 ROI 预览，不应改变动作识别结果。

## 可选动作

测试前逐项勾选对应输入。

输入管理菜单：

- 点击“输入管理”，确认出现轮询选项。
- 两次短眨选择当前高亮项，确认可切换抬眉、张嘴、微笑、摇头；抬眉已开启时，也可用抬眉选择。
- 选择“仅用眨眼”后，抬眉、张嘴、微笑、摇头应全部关闭，眨眼短码仍保持开启。
- 单次长闭眼应被忽略；闭眼 3 秒以上才退出输入管理。
- 输入管理中开启摇头后，轻微摇头不应退出输入管理；摇头只在挠痒痒/调整体位等普通二级选择里取消。
- 输入管理中选择任一开关后，约 `0.7 秒` 内再次两次短眨不应误选下一项；严格三短眨紧急求助仍应可触发。
- 完成校准确认后，测试 `长闭眼 + 长闭眼 + 短眨`，第二次长闭眼后约 `1.6 秒` 内接短眨，应进入输入管理菜单；整体动作允许最长约 `9 秒`。

- 抬眉：头部尽量稳定，轻抬眉约 `0.25 秒` 后放松；再单独测试上下点头，确认不会误触抬眉。
- 张嘴2次：微张嘴约 `0.2 秒` 后闭合，约 `2 秒` 内重复两次；单次张嘴应静默清空，不显示半触发提示；观察是否还会带动抬眉误报。
- 微笑：先保持自然表情约 1 秒，再轻微闭嘴微笑并保持约 `0.8 秒` 后放松；观察嘴角横向距离增长是否能触发，左右摇头时不应触发。
- 摇头：极轻微左-右-左或右-左-右，`4 秒` 内完成。

## 重点观察

- 是否出现非当前规则的旧版语义。
- 手机或 Mac 画面中人脸偏小、偏边、明显抖动时，人脸质量提示是否准确；质量不足但眼睛仍可用时，可选面部动作应暂停，眨眼短码、长闭眼退出/安静和安静恢复应保留；质量门控关闭后，动作识别是否恢复原行为。
- 人脸近景框是否完整包住眉毛、眼睛、嘴和下巴；框是否平滑、不突跳；关闭后是否只剩面部描边。
- 长闭眼2次是否被静默忽略。
- 短眨+长闭眼是否稳定触发挠痒痒。
- 张嘴2次和微笑是否仍会互相混淆。
- 摇头是否能用更小幅度触发，且不会因画面位移误触，也不会触发微笑。
- 微笑单次等待约 1.4 秒是否可以接受。
- 摄像头画面是否还会明显自动缩放；若出现“画面稳定中”，观察这段时间是否不再触发可选动作。
- TTS 播报是否明显慢于文字显示。
