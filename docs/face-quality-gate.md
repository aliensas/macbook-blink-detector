# 人脸质量门控

## 目标

这个功能用于减少 iPhone 广角、距离过远、脸部偏边缘或画面抖动造成的误触。

当前版本只做第一阶段：

```text
现有 Face Landmarker 输出
→ 根据关键点估算人脸质量
→ 根据质量策略决定允许所有动作、仅允许眼部输入，或暂停患者动作
```

它不改变摄像头输入，不裁剪 ROI，不增加第二个模型，也不替换原有动作识别逻辑。

## 独立边界

实现集中在：

```text
src/shared/face-quality.js
```

页面只接入三个点：

- 显示人脸质量状态条。
- 提供“质量不足时暂停可选面部动作”开关。
- 在动作真正执行前检查质量门控。

如果后续测试发现不好用，可以删除该模块和这几处接线，动作配置、短码、二级菜单和输入管理逻辑不需要回滚。

## 当前评估指标

质量评估只使用 478 个关键点的几何信息：

- 人脸高度占画面比例。
- 人脸面积占画面比例。
- 人脸中心是否偏离画面中心。
- 眉毛、嘴部、下巴是否接近画面边缘。
- 最近几帧关键点框是否明显抖动。
- 眼部关键点是否仍可稳定用于严格眨眼输入。

暂不做光照、模糊、ROI 裁剪或自动变焦。

## 触发规则

默认开启门控。

质量策略分三档：

```text
all
→ 质量良好或可用，允许当前模式下的已开启动作。

eyesOnly
→ 整体质量不足，但眼部关键点仍可用。
→ 暂停抬眉、张嘴、微笑、摇头等可选面部动作；保留眨眼短码、闭眼 3-8 秒退出、闭眼 8 秒安静模式、安静模式短眨恢复。

none
→ 未见人脸或眼部关键点不可用。
→ 暂停患者动作触发。
```

质量不足时：

```text
可选动作检测器重置
屏幕提示调整手机位置
眼部仍可用时允许眨眼短码；眼部不可用或无脸时不播报护理指令
```

## 测试重点

- iPhone 前置广角下，人脸偏小时是否提示“人脸偏小”。
- 患者脸靠边时是否提示“人脸接近画面边缘”或“人脸偏离中心”。
- 手机抖动、护理员碰到手机时，是否短暂暂停触发。
- 质量门控开启时，低质量画面是否能减少张嘴、微笑、摇头误触。
- 质量门控关闭后，动作识别是否恢复原来的行为。

## 后续阶段

只有当第一阶段证明有帮助，再考虑：

```text
阶段 2：稳定 ROI 预览，不改变识别输入（已作为独立预览功能加入）
阶段 3：如需重新验证 ROI 输入，必须放在独立分支，默认不进入稳定版
```
