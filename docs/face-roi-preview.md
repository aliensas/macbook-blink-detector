# 人脸 ROI 预览

## 目标

这是手机广角问题的第二阶段验证功能。

当前只做：

```text
现有 Face Landmarker 关键点
→ 估算人脸 bbox
→ 向外扩展成 ROI 近景框
→ 做平滑追踪
→ 画在摄像头 overlay 上
```

它不改变 Face Landmarker 的输入，不裁剪视频，不改变任何动作识别阈值，也不参与动作触发。

## 独立边界

核心实现集中在：

```text
src/shared/face-roi-preview.js
```

主页面只接入：

- “人脸近景框”开关。
- 在 overlay canvas 上绘制 ROI 预览框。

如果后续测试发现 ROI 框跳动、遮挡、干扰患者观察，删除这个模块和对应 UI 接线即可，不需要回滚眨眼、可选动作、二级菜单或输入管理逻辑。

## 当前绘制规则

- 使用全部有效人脸关键点估算原始 bbox。
- bbox 向外扩展，尽量包含眉毛、眼睛、嘴角、下巴和轻微头部移动空间。
- ROI 框做指数平滑，避免每帧跳动。
- 黄色虚线表示仍在稳定中。
- 紫色虚线表示连续稳定若干帧。

## 当前不做

- 不做真正 ROI 输入。
- 不做自动变焦。
- 不做双模型人脸检测。
- 不用 ROI 框影响动作触发。
- 不在低质量时自动裁剪或重新定位。

## 测试重点

- iPhone 前置广角下，ROI 框是否能包住完整眉毛、眼睛、嘴和下巴。
- 患者轻微摇头、张嘴、微笑时，ROI 框是否稳定，不突然跳动。
- 患者脸靠边或护理员进入画面时，ROI 框是否出现明显错误。
- 关闭“人脸近景框”后，画面是否恢复到只有面部描边。
- ROI 框本身是否干扰患者或照护者查看输出。

## 后续条件

只有当 ROI 预览在多次真机测试中稳定、边界合理、没有明显误导，才考虑第三阶段：

```text
实验性 ROI 输入模式
```

第三阶段必须默认关闭，并单独比较延迟、发热、识别稳定性和误触率。
