# v0.3 Action Config 设计文档

## 1. 目标

v0.3 的核心目标不是增加更多检测算法，而是把“检测到的动作”和“动作代表的含义”分离。

```text
面部动作检测层
→ 动作事件
→ 动作含义配置
→ 屏幕文字 / 语音播报 / 确认流程
```

这样后续加入高级设置时，用户修改的是动作含义配置，不是底层检测逻辑。

本阶段仅考虑 Mac 本地版，待 Mac 本地版测试定版后再考虑其他平台。

## 2. 设计原则

1. 动作不是意图，动作只是输入信号。
2. 动作检测逻辑不应直接写死播报文本。
3. 默认配置必须低疲劳、低误触、容易被照护者理解。
4. 高风险护理动作要更保守，不能因为可自定义而变得危险。
5. 情感表达是 AAC 的重要能力，不应只提供护理和求助短语。
6. 高级设置只改变语义配置，不改变 EAR、阈值、帧数、blendshape 等底层检测参数。

## 3. 动作配置字段

每个动作配置包含：

```js
{
  id: "blink_double_short_help",
  gestureId: "blink_double_short",
  label: "短眨2次",
  displayText: "我需要帮助，请过来一下",
  speechText: "我需要帮助，请过来一下",
  category: "help",
  enabled: true,
  speak: true,
  requiresConfirmation: false,
  locked: false,
  editable: {
    displayText: true,
    speechText: true,
    enabled: true,
    speak: true,
    requiresConfirmation: false
  }
}
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `id` | 语义配置 ID，表示这一条动作含义 |
| `gestureId` | 检测层输出的动作 ID |
| `label` | 界面给照护者看的动作名称 |
| `displayText` | 屏幕显示文本 |
| `speechText` | TTS 播报文本 |
| `category` | `help` / `care` / `emergency` / `emotion` / `control` |
| `enabled` | 是否启用该动作含义 |
| `speak` | 触发后是否自动播报 |
| `requiresConfirmation` | 是否需要二次确认 |
| `locked` | 是否保护，避免用户误删或改坏 |
| `editable` | 高级设置中允许修改的字段 |

## 4. v0.3 默认配置表

| 配置 ID | 检测动作 | 默认显示 / 播报 | 类型 | 默认启用 | 播报 | 确认 | 保护 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `blink_double_short_help` | 短眨2次 | 我需要帮助，请过来一下 | help | 是 | 是 | 否 | 否 |
| `blink_triple_short_emergency` | 短眨3次 | 紧急求助，请马上查看 | emergency | 是 | 是 | 否 | 是 |
| `blink_double_long_rest` | 长闭眼2次 | 我想休息 | control | 是 | 是 | 否 | 否 |
| `blink_short_long_scratch` | 短眨 + 长闭眼 | 我想挠痒痒 | care | 是 | 是 | 否 | 否 |
| `blink_long_short_position` | 长闭眼 + 短眨 | 我想调整体位 | care | 是 | 是 | 否，后续可开启 | 否 |
| `brow_raise_yes` | 抬眉 | 是 / 确认 | control | 可选 | 是 | 否 | 否 |
| `mouth_double_open_suction` | 张嘴2次 | 我需要吸痰，请马上查看 | care | 可选 | 是 | 否 | 否 |
| `smile_status` | 微笑 | 谢谢，可以，我还好 | emotion | 可选 | 是 | 否 | 否 |
| `smile_double_love` | 微笑2次 | 我爱你们 | emotion | 可选 | 是 | 否 | 否 |
| `head_shake_no` | 摇头 | 否，不是，取消 | control | 可选 | 是 | 否 | 否 |

补充说明：

- 长闭眼不是一直闭着不动；有效动作是“闭眼约 1 秒后睁开”。当前有效范围约 `0.7-2.8 秒`，超过休息阈值会被当作闭眼休息观察，不作为长闭眼短码。
- `短眨 + 长闭眼` 的用户操作是“短眨并睁开 -> 约 `2.5 秒` 内开始长闭眼 -> 长闭眼约 1 秒 -> 睁开”。系统在最后睁开后结算。
- `长闭眼 + 短眨` 当前直接表达“我想调整体位”；如果真实测试中误触明显，再开启确认流程。
- `微笑2次` 作为默认情感表达动作，用于“我爱你们”；高级设置中可改成“我爱你”或其他家庭表达。
- 口腔护理暂不占用默认短码，后续可通过高级设置或护理菜单加入。

## 5. 检测动作 ID 建议

检测层只输出标准动作事件，不关心语义：

| `gestureId` | 来源 |
| --- | --- |
| `blink_single_short` | 单次短眨 |
| `blink_single_long` | 单次长闭眼 |
| `blink_double_short` | 短眨2次 |
| `blink_triple_short` | 短眨3次 |
| `blink_double_long` | 长闭眼2次 |
| `blink_short_long` | 短眨 + 长闭眼 |
| `blink_long_short` | 长闭眼 + 短眨 |
| `brow_raise` | 抬眉 |
| `mouth_double_open` | 张嘴2次 |
| `smile` | 微笑 |
| `smile_double` | 微笑2次 |
| `head_shake` | 摇头 |

单次短眨默认不映射任何语义，避免自然眨眼误触。

## 6. 高级设置允许修改的内容

高级设置第一版只允许修改：

- 显示文本 `displayText`
- 播报文本 `speechText`
- 是否启用 `enabled`
- 是否播报 `speak`
- 是否需要确认 `requiresConfirmation`

不允许在第一版高级设置中修改：

- 动作检测阈值
- 眨眼 EAR 参数
- blendshape 阈值
- 头部姿态阈值
- 动作窗口时间
- `gestureId`
- `category`
- `locked`

这样可以降低误操作风险。

## 7. 安全规则

### 7.1 紧急求助

`blink_triple_short_emergency` 默认保护：

- 不建议允许关闭。
- 可以允许修改播报文本。
- 不建议允许改成低风险含义。
- 不建议加入确认流程，因为紧急求助应优先快速发出。

### 7.2 护理类动作

护理类包括：

- 吸痰
- 调整体位
- 挠痒痒
- 口腔护理
- 疼痛
- 呼吸不适

护理类动作默认可以播报，但进入临床/真实护理测试前，需要由患者和照护者确认该动作稳定、低疲劳、低误触。

其中吸痰和体位调整属于更高风险护理提示。后续如果误触明显，应开启确认流程。

### 7.3 情感表达

情感表达默认不需要确认，因为误触风险相对低于护理操作。

建议默认提供：

```text
微笑：谢谢，可以，我还好
微笑2次：我爱你们
```

高级设置中可以改成：

- 我爱你
- 我爱你们
- 谢谢你
- 辛苦你了
- 我很安心
- 你在我身边我很高兴

### 7.4 取消与否定

摇头和长闭眼在不同上下文中可能有不同含义：

| 上下文 | 动作 | 含义 |
| --- | --- | --- |
| 普通状态 | 摇头 | 否，不是，取消 |
| 确认窗口 | 摇头 | 取消 |
| 确认窗口 | 单次长闭眼 | 取消 |
| 体位/菜单状态 | 摇头 | 退出或表示不舒服 |

上下文优先级必须高于全局语义，避免同一个动作在确认窗口里触发错误短语。

## 8. 本地保存策略

高级设置配置只保存在当前 Mac 本机。

建议使用一个新的 localStorage key：

```text
alsFacialAac.actionConfig.v1
```

保存内容只包含用户修改过的配置字段。默认配置仍写在代码中，启动时按以下顺序合并：

```text
默认配置
→ 本机保存的用户配置
→ 运行时状态
```

必须提供：

- 保存设置
- 取消修改
- 恢复默认设置
- 测试播报

## 9. UI 展示规则

普通界面只显示当前启用动作说明。

示例：

```text
当前动作说明
短眨2次：我需要帮助，请过来一下
短眨3次：紧急求助
长闭眼2次：我想休息
```

如果启用了可选动作，再追加：

```text
抬眉：是 / 确认
张嘴2次：我需要吸痰
微笑：谢谢，可以，我还好
微笑2次：我爱你们
摇头：否，不是，取消
```

普通患者界面不显示工程测试记录。工程数据继续放在调试/工程模式中。

## 11. 本阶段不做

本阶段暂不做：

- 完整摩尔斯输入。
- 多层复杂菜单。
- 远程同步配置。
- 多患者云端档案。
- 让普通用户修改底层检测阈值。

先把 Mac 本地版的动作含义配置跑稳，再考虑平台移植和更复杂的 AAC 扩展。
