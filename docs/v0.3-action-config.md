# v0.3 Action Config 设计文档

## 1. 目标

v0.3 的核心目标不是增加更多检测算法，而是把“检测到的动作”和“动作代表的含义”分离。

```text
面部动作检测层
→ 动作事件
→ 动作含义配置
→ 屏幕文字 / 语音播报 / 确认流程
```

这样后续加入高级设置时，用户修改的是动作含义配置，不是底层检测逻辑。

本阶段仅考虑 Mac 本地版，待 Mac 本地版测试定版后再考虑其他平台。

## 2. 设计原则

1. 动作不是意图，动作只是输入信号。
2. 动作检测逻辑不应直接写死播报文本。
3. 默认配置必须低疲劳、低误触、容易被照护者理解。
4. 高风险护理动作要更保守，不能因为可自定义而变得危险。
5. 情感表达是 AAC 的重要能力，不应只提供护理和求助短语。
6. 高级设置只改变语义配置，不改变 EAR、阈值、帧数、blendshape 等底层检测参数。

## 3. 动作配置字段

每个动作配置包含：

```js
{
  id: "blink_double_short_help",
  gestureId: "blink_double_short",
  label: "短眨2次",
  text: "我需要帮助，请过来一下",
  category: "help",
  enabled: true,
  requiresConfirmation: false,
  locked: false,
  editable: {
    text: true
  }
}
```

字段说明：

| 字段 | 含义 |
| --- | --- |
| `id` | 语义配置 ID，表示这一条动作含义 |
| `gestureId` | 检测层输出的动作 ID |
| `label` | 界面给照护者看的动作名称 |
| `text` | 屏幕显示和 TTS 播报共用的表达文字 |
| `category` | `help` / `care` / `emergency` / `emotion` / `control` |
| `enabled` | 是否启用该动作含义 |
| `requiresConfirmation` | 是否需要二次确认 |
| `locked` | 是否保护，避免用户误删或改坏 |
| `editable` | 高级设置中允许修改的字段 |

## 4. v0.3 默认配置表

| 配置 ID | 检测动作 | 默认显示 / 播报 | 类型 | 默认启用 | 播报 | 确认 | 保护 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `blink_double_short_help` | 短眨2次 | 我需要帮助，请过来一下 | help | 是 | 是 | 否 | 否 |
| `blink_triple_short_emergency` | 短眨3次 | 紧急求助，请马上查看 | emergency | 是 | 是 | 否 | 是 |
| `blink_short_long_scratch` | 短眨 + 长闭眼 | 我想挠痒痒，进入位置二级选择 | care | 是 | 是 | 否 | 否 |
| `blink_long_short_position` | 长闭眼 + 短眨 | 我想调整体位，进入方式二级选择 | care | 是 | 是 | 否 | 否 |
| `blink_long_long_short_input_management` | 长闭眼 + 长闭眼 + 短眨 | 进入输入管理 | control | 是 | 否 | 否 | 否 |
| `brow_raise_yes` | 抬眉 | 是 / 确认 | control | 可选 | 是 | 否 | 否 |
| `mouth_double_open_suction` | 张嘴2次 | 我需要吸痰，请马上查看 | care | 可选 | 是 | 否 | 否 |
| `smile_status` | 微笑 | 谢谢，可以，我还好 | emotion | 可选 | 是 | 否 | 否 |
| `smile_double_love` | 微笑2次 | 我爱你 | emotion | 可选 | 是 | 否 | 否 |
| `head_shake_no` | 摇头 | 否，不是，取消 | control | 可选 | 是 | 否 | 否 |

补充说明：

- 长闭眼短码不是一直闭着不动；有效动作是“闭眼约 1 秒后睁开”。当前短码有效范围约 `0.7-2.8 秒`。闭眼 `3 秒以上、不足 8 秒` 只在二级选择、确认窗口、输入管理等流程中退出；等待输入状态下只清空未完成短码，不显示、不播报。闭眼 `8 秒以上` 即使未睁开也进入系统安静模式。安静模式中连续 3 次短眨会等待第 4 次；第 4 次出现则恢复，第 4 次未在窗口内出现则触发紧急求助。
- 眨眼短码必须连续：短眨后约 `1.2 秒` 内开始下一次动作，长闭眼后约 `1.6 秒` 内开始下一次动作；间隔过长会静默清空，不显示“未识别编码”，不触发指令。
- `短眨 + 长闭眼` 的用户操作是“短眨并睁开 -> 约 `1.2 秒` 内开始长闭眼 -> 长闭眼约 1 秒 -> 睁开”。系统在最后睁开后结算。
- `短眨 + 长闭眼` 触发挠痒痒二级选择；`长闭眼 + 短眨` 触发调整体位二级选择。二级选择会自动轮流高亮选项；第一次短眨锁定当前高亮项，第二次短眨选择锁定项；轻抬眉后放松也可选择，闭眼 3 秒以上或摇头退出。
- `长闭眼 + 长闭眼` 当前无默认动作，不显示、不播报；系统只短暂等待是否续接短眨。`长闭眼 + 长闭眼 + 短眨` 触发输入管理菜单。眨眼短码是基础输入通道，始终开启，不能关闭。输入管理菜单也可以从右侧“输入管理”按钮进入，只控制抬眉、张嘴、微笑、摇头这些可选通道，并把开关状态保存到本机。输入管理内用两次短眨选择；若抬眉已开启，也可抬眉选择；长闭眼 `3 秒以上、不足 8 秒` 退出；摇头在输入管理内忽略，避免刚开启摇头时误退出。
- 直接播报类动作触发后必须结束本次输入回合：保留上一句输出，清空短码、确认窗口、无关二级状态和临时动作序列，约 `2 秒` 内忽略普通新输入，状态回到等待输入；严格三短眨紧急求助可以打断普通冷却。
- 二级菜单类动作例外：`短眨 + 长闭眼`、`长闭眼 + 短眨`、`长闭眼 + 长闭眼 + 短眨` 会进入轮询菜单，不立即回到等待输入。
- 程序动作触发后会进入短暂冷却；冷却只用于防止同一串动作尾部重复触发，不影响单个自然眨眼被忽略。
- `微笑2次` 作为默认情感表达动作，用于“我爱你”；必须先完全放松约 `0.5 秒` 再第二次微笑，避免一次微笑抖动被当成双微笑。
- 口腔护理暂不占用默认短码，后续可通过高级设置或护理菜单加入。
- 可选动作先按低疲劳测试调校：抬眉轻抬约 `0.25 秒` 后放松，检测到上下点头或画面上下位移时会临时暂停抬眉判断；张嘴只需微张约 `0.2 秒` 后闭合且约 `2 秒` 内重复两次，单次张嘴静默清空；张嘴信号出现时会临时抑制抬眉，只有明显张嘴才会抑制微笑；微笑使用嘴角横向距离相对个人基线的增长量，轻微闭嘴微笑约 `0.25 秒` 后放松，检测到左右方向切换的摇头时会短暂暂停微笑判断；微笑两次中间必须完全放松约 `0.5 秒`；摇头在 `4 秒` 内极轻微左右变化。

## 5. 检测动作 ID 建议

检测层只输出标准动作事件，不关心语义：

| `gestureId` | 来源 |
| --- | --- |
| `blink_single_short` | 单次短眨 |
| `blink_single_long` | 单次长闭眼 |
| `blink_double_short` | 短眨2次 |
| `blink_triple_short` | 短眨3次 |
| `blink_short_long` | 短眨 + 长闭眼 |
| `blink_long_short` | 长闭眼 + 短眨 |
| `input_management` | 长闭眼 + 长闭眼 + 短眨 |
| `brow_raise` | 抬眉 |
| `mouth_double_open` | 张嘴2次 |
| `smile` | 微笑 |
| `smile_double` | 微笑2次 |
| `head_shake` | 摇头 |

嘴部补充捕捉点：

| 特征 | 关键点 | 用途 |
| --- | --- | --- |
| `mouth_open_vertical` | 上下唇内侧 `13` / `14` | 张嘴、吸痰候选动作 |
| `mouth_width` | 左右嘴角 `61` / `291` | 闭嘴微笑判断，使用相对个人基线的横向增长量；左右方向切换的摇头时暂停使用 |
| `head_pitch` | 鼻尖 `1` 相对眼外角 `33` / `263` | 上下点头时抑制抬眉误报 |
| `face_center_y` | 脸部上缘 `10` / 下巴 `152` | 画面上下位移时抑制抬眉误报 |

单次短眨默认不映射任何语义，避免自然眨眼误触。

## 6. 高级设置允许修改的内容

v0.4 已收紧高级设置范围，最新实现口径以 `docs/v0.4-action-config.md` 为准：高级设置只允许修改一条“表达文字”，屏幕显示和语音播报使用同一句，不允许关闭显示，不允许关闭播报。

v0.3 阶段曾考虑允许分别修改显示和播报，但 v0.4 已取消双字段：

- 表达文字 `text`
- 是否启用 `enabled`
- 是否需要确认 `requiresConfirmation`

其中 `enabled` 和 `requiresConfirmation` 不进入 v0.4 第一版高级设置，避免普通照护场景误配置。

不允许在第一版高级设置中修改：

- 动作检测阈值
- 眨眼 EAR 参数
- blendshape 阈值
- 头部姿态阈值
- 动作窗口时间
- `gestureId`
- `category`
- `locked`

这样可以降低误操作风险。

## 7. 安全规则

### 7.1 紧急求助

`blink_triple_short_emergency` 默认保护：

- 不建议允许关闭。
- 可以允许修改播报文本。
- 不建议允许改成低风险含义。
- 不建议加入确认流程，因为紧急求助应优先快速发出。

### 7.2 护理类动作

护理类包括：

- 吸痰
- 调整体位
- 挠痒痒
- 口腔护理
- 疼痛
- 呼吸不适

护理类动作默认可以播报，但进入临床/真实护理测试前，需要由患者和照护者确认该动作稳定、低疲劳、低误触。

其中吸痰和体位调整属于更高风险护理提示。后续如果误触明显，应开启确认流程。

### 7.3 情感表达

情感表达默认不需要确认，因为误触风险相对低于护理操作。

建议默认提供：

```text
微笑：谢谢，可以，我还好
微笑2次：我爱你
```

高级设置中可以改成：

- 我爱你
- 谢谢你
- 辛苦你了
- 我很安心
- 你在我身边我很高兴

### 7.4 取消与否定

摇头和长闭眼在不同上下文中可能有不同含义：

| 上下文 | 动作 | 含义 |
| --- | --- | --- |
| 普通状态 | 摇头 | 否，不是，取消 |
| 确认窗口 | 摇头 | 取消 |
| 确认窗口 | 闭眼 3 秒以上 | 取消/退出 |
| 体位/菜单状态 | 摇头 | 退出或表示不舒服 |

上下文优先级必须高于全局语义，避免同一个动作在确认窗口里触发错误短语。

## 8. 本地保存策略

高级设置配置只保存在当前 Mac 本机。

v0.3 曾建议使用：

```text
alsFacialAac.actionConfig.v1
```

v0.4 第一版实现不继续使用 `v1`，改用单字段表达文字配置，并且只保存用户修改过的表达文字。默认配置仍写在代码中，启动时按以下顺序合并：

```text
默认配置
→ 本机保存的用户配置
→ 运行时状态
```

必须提供：

- 保存设置
- 取消修改
- 恢复默认设置
- 测试播报

v0.4 使用：

```text
alsFacialAac.actionText.v1
```

## 9. UI 展示规则

普通界面只显示当前启用动作说明。

示例：

```text
当前动作说明
短眨2次：我需要帮助，请过来一下
短眨3次：紧急求助
长闭眼2次：无默认动作
```

如果启用了可选动作，再追加：

```text
抬眉：是 / 确认
张嘴2次：我需要吸痰
微笑：谢谢，可以，我还好
微笑2次：我爱你
摇头：否，不是，取消
```

普通患者界面不显示工程测试记录。工程数据继续放在调试/工程模式中。

## 11. 本阶段不做

本阶段暂不做：

- 完整摩尔斯输入。
- 多层复杂菜单。
- 远程同步配置。
- 多患者云端档案。
- 让普通用户修改底层检测阈值。

先把 Mac 本地版的动作含义配置跑稳，再考虑平台移植和更复杂的 AAC 扩展。
