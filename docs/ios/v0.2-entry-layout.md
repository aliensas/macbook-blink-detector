# iOS v0.2 入口与布局方案

## 1. 当前决策

iOS 第一阶段不复制一份完整 HTML，也不单独维护一套动作逻辑。

采用：

```text
/ios/
  -> 跳转到 /?platform=ios
  -> 使用同一套 index.html 和 src/main.js
  -> 只启用 iOS 专用布局规则
```

这样做的目的是避免 Mac 和 iOS 出现两份页面结构、两份按钮、两份动作说明，后续难以保持一致。

## 2. 访问地址

开发模式：

```text
http://127.0.0.1:5173/ios/
```

实际运行会进入：

```text
http://127.0.0.1:5173/?platform=ios
```

Mac 默认地址仍然是：

```text
http://127.0.0.1:5173/
```

iPhone 真机测试需要从手机访问 Mac 的局域网地址，并且摄像头通常需要 HTTPS。使用：

```bash
npm run dev:ios
```

该命令会：

- 生成本地 HTTPS 测试证书到 `.cert/`。
- 绑定 `0.0.0.0`，让同一 Wi-Fi 下的 iPhone 可以访问。
- 打印类似 `https://192.168.x.x:5175/ios/` 的 iPhone 测试地址。

如果 Safari 提示证书风险，测试阶段可以继续访问。若 iPhone 仍不允许摄像头，需要把 `.cert/ios-dev-cert.pem` 安装并信任到 iPhone，或改用已受信任的 HTTPS 域名 / 隧道服务。

## 3. 为什么不复制 HTML

当前 `src/main.js` 绑定了完整主界面 DOM：

- 摄像头预览。
- 通信输出。
- 二级选择。
- 输入管理。
- 高级设置。
- 引导校准。
- 工程测试。

如果为 iOS 复制一份完整 HTML，后续每次改按钮、文案、动作说明、辅助设置，都要同步两处，容易产生旧逻辑残留。

所以 v0.2 先保持：

```text
一套 DOM
一套动作核心
一套检测主流程
两套布局表现
```

## 4. iOS 布局规则

只有 `?platform=ios` 启用 iOS 专用规则。

竖屏：

- 页面固定在一个视口内。
- 摄像区在上方，比例固定为 `4 / 3`。
- 输出和按钮不会改变摄像区比例。
- 下方控制面板独立滚动。

横屏：

- 左侧为摄像和输出。
- 右侧为操作面板。
- 摄像区比例固定为 `16 / 9`。
- 右侧操作面板独立滚动。

## 5. 当前验证目标

需要重点验证：

- iPhone 15 Pro 竖屏 `393 x 852`。
- iPhone 15 Pro Max 竖屏 `430 x 932`。
- iPhone 15 Pro 横屏 `852 x 393`。
- iPhone 15 Pro Max 横屏 `932 x 430`。
- 摄像区不会因输出文字或二级菜单展开而缩放。
- 操作面板可以滚动，摄像区保持稳定。

## 6. 后续 App 外壳

如果 iPhone Safari / PWA 验证通过，再考虑：

```text
同一套 Web 应用
  -> Capacitor / WKWebView
  -> Xcode 真机安装
```

如果 WebView 摄像头、TTS 或性能不足，再评估更深的原生 iOS 实现。
