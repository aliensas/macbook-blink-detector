# iOS 版本 v0.2 当前计划

## 1. 当前结论

iOS 版本继续定位为：

```text
ALS 面部微动作 AAC 输入原型 - iPhone 版
```

它不是医疗诊断工具，也不替代专业 AAC 设备。目标是把患者仍能稳定、低疲劳完成的少数面部动作，转换成屏幕文字和语音表达。

v0.2 不直接从旧 iOS 草稿继续改，而是从当前 Mac 稳定版出发，迁移已经测试过的核心逻辑。原因是 Mac 版近期已经修正了多处关键问题，iOS 版不能重新走旧逻辑。

## 2. 本分支边界

分支：

```text
codex/ios-aac-app-v02
```

文档路径：

```text
docs/ios/
```

iOS 工作区：

```text
ios/
```

原则：

- 不影响 Mac 本地版主线。
- 不把 iOS 临时代码混进 Mac 桌面布局。
- 不复制旧逻辑后长期分叉。
- 优先抽出可共享的动作解释、配置、二级选择和输入管理规则。
- 平台相关内容，如布局、摄像头权限、TTS 细节，在 iOS 路径中单独处理。

## 3. 必须继承的 Mac 稳定能力

第一阶段 iOS 版必须继承这些能力：

| 功能 | iOS v0.2 要求 |
| --- | --- |
| 眨眼短码 | 保留当前短码表和防误触规则 |
| 二级选择 | 挠痒痒、调整体位继续使用轮询选择 |
| 二级菜单确认 | 两次短眨只选择当前项，不能继续触发全局帮助 |
| 输入管理 | 眨眼不能关闭，抬眉、张嘴、微笑、摇头可开关 |
| 高级设置 | 每个动作只设置一条表达文字，文字和语音一致 |
| 本地保存 | 保存当前患者配置到本机浏览器或 App 本地存储 |
| 中英文界面 | 支持中文 / English 切换 |
| TTS | 中文和英文语音处理隔离，英文优化不能影响中文 |
| 摄像画面 | 固定比例，不随长文字或按钮展开突然缩放 |

## 4. 第一阶段不做

v0.2 暂不做：

- App Store 上架。
- 云端账户。
- 多患者云同步。
- 远程通知照护者。
- 医疗设备联动。
- 完整原生重写面部识别。
- 在 iOS 上重新设计一套不同的动作含义。

## 5. 技术路线

先走最小风险路线：

```text
当前 Mac 稳定逻辑
        ↓
抽出共享动作核心
        ↓
iPhone 专用移动布局
        ↓
iPhone Safari / PWA 真机测试
        ↓
再评估 Capacitor / WKWebView / Xcode 打包
```

不要一开始直接生成复杂 Xcode 工程。先确认 iPhone Safari 中摄像头、MediaPipe、TTS、布局和本地存储都可接受。

## 6. iPhone 适配重点

优先设备：

- iPhone 15 Pro
- iPhone 15 Pro Max

竖屏要求：

- 摄像画面在上方或核心区域，比例固定。
- 当前输出文字清晰，不挤压摄像画面。
- 常用动作说明只显示已启用动作。
- 输入管理和高级设置可以滚动，但摄像区域不应随文字变化跳动。

横屏要求：

- 摄像区域和操作区左右分栏。
- 摄像区域固定比例。
- 操作区可滚动。
- 二级选择高亮项足够大，照护者能看清。

## 7. iOS 关键风险

必须真实验证：

- iPhone 前置摄像头权限是否稳定。
- HTTPS / PWA / WebView 下摄像头是否可用。
- MediaPipe WASM 在 iPhone 上是否足够快。
- 长时间运行是否发热、掉帧或暂停。
- 切到后台、锁屏、来电后摄像头是否中断。
- iOS TTS 首次播报是否延迟明显。
- 中英文 TTS 是否选到奇怪声音。
- localStorage 或 App 本地存储是否可靠。
- 横屏 / 竖屏切换时摄像画面是否重置或变形。

## 8. 动作逻辑迁移规则

动作含义以当前 action config 为准：

| 动作 | 默认表达 |
| --- | --- |
| 短眨2次 | 我需要帮助，请过来一下 |
| 短眨3次 | 紧急求助，请马上查看 |
| 长闭眼2次 | 我想休息 |
| 短眨 + 长闭眼 | 我想挠痒痒 |
| 长闭眼 + 短眨 | 我想调整体位 |
| 抬眉 | 是，确认 |
| 张嘴2次 | 我需要吸痰，请马上查看 |
| 摇头 | 否，不是，取消 |
| 微笑 | 谢谢，可以，我还好 |
| 微笑2次 | 我爱你 |

二级选择规则：

- 触发挠痒痒或调整体位后进入轮询菜单。
- 两次短眨选择当前高亮项。
- 如果抬眉已启用，抬眉也可以选择当前高亮项。
- 长闭眼取消二级菜单。
- 被二级菜单消费的两次短眨，不能再触发全局帮助。

输入管理规则：

- 眨眼短码始终开启，不能关闭。
- 患者可通过短码进入输入管理。
- 抬眉、张嘴、微笑、摇头可以逐项开启或关闭。
- 被关闭的动作只显示实时信号或不解释，不触发播报。

## 9. 第一轮真机测试清单

1. iPhone Safari 打开 HTTPS 地址。
2. 允许前置摄像头。
3. 确认人脸描边和眼睛开合条正常。
4. 测试短眨2次、短眨3次、长闭眼2次。
5. 测试短眨 + 长闭眼进入挠痒痒。
6. 测试长闭眼 + 短眨进入调整体位。
7. 测试二级菜单中两次短眨不会再触发“需要帮助”。
8. 开启抬眉，测试二级菜单中抬眉选择。
9. 分别开启张嘴、摇头、微笑，测试是否误触过多。
10. 切换英文，测试界面和语音。
11. 切回中文，确认中文语音没有被英文设置影响。
12. 横屏和竖屏分别测试布局。
13. 锁屏、切后台、接电话模拟后重新进入。

## 10. 下一步实施顺序

1. 建立 iOS 工作区文档和边界。
2. 抽出共享动作配置和解释逻辑的候选模块。
3. 做 iPhone 专用页面布局，不改变 Mac 桌面布局。
4. 用局域网 HTTPS 在 iPhone Safari 测试。
5. 根据真机结果决定 PWA、Capacitor 或更深的原生方案。

已完成：

- 建立 `src/shared/action-core.js` 作为 Mac / iOS 共用动作核心候选模块。
- 已抽出动作默认配置、英文动作本地化、眨眼短码映射、事件动作映射。
- 已抽出挠痒痒、调整体位、输入管理的二级选择配置和英文二级选择本地化。

- 增加 iPhone 竖屏和横屏专用布局约束，默认 Mac 地址不启用这些规则。
