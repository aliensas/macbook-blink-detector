# Mac 本地稳定版基线

本文记录 Mac 本地版当前稳定规则、回归测试范围和维护边界。目标是让后续修改更容易判断是否破坏了患者可用链路。

## 当前稳定输入规则

- 单次短眨：不触发通信动作。
- 两次短眨：我需要帮助，请过来一下。
- 三次短眨：紧急求助，请马上查看。
- 短眨 + 长闭眼：进入挠痒痒二级菜单。
- 长闭眼 + 短眨：进入调整体位二级菜单。
- 长闭眼 + 长闭眼 + 短眨：进入输入管理。
- 单次长闭眼短码、两次长闭眼短码：不触发护理短语。

## 二级菜单规则

- 单次短眨：不锁定、不暂停轮询。
- 第二次短眨：锁定第二次短眨发生时的当前高亮项。
- 第二次短眨后继续等待第三次短眨窗口。
- 第三次短眨出现：触发紧急求助，不选择菜单项。
- 第三次短眨未出现：选择第二次短眨时锁定的项目。
- 长闭眼 3 秒以上：退出当前菜单，回到等待输入。

## 长闭眼和安静模式

- 闭眼 3-8 秒后睁眼：退出当前菜单、输入管理或确认窗口；如果已经在等待输入，只清空缓存。
- 闭眼达到 8 秒：进入安静模式。
- 安静模式中连续 4 次短眨：恢复普通识别；恢复用短眨允许略慢，闭眼可到约 1 秒；每两次短眨可间隔约 3 秒，整体约 12 秒内完成。
- 安静模式中 3 次短眨后约 3 秒内无第 4 次：触发紧急例外。

## 输入通道

- 眨眼短码始终开启。
- 抬眉、张嘴、微笑、摇头是可选通道，可由输入管理开启或关闭。
- 可选动作默认不应替代眨眼主链路。

## 每次改动后至少回归

```text
npm run test:logic
node --check src/main.js
node --check src/shared/aac-input-machine.js
npm run build
git diff --check
```

浏览器实测：

- 页面能打开，摄像头能启动。
- 刚启动后的第一次 `..` 和 `...` 能响应。
- `.-` 和 `-.` 能进入对应二级菜单。
- 二级菜单单次短眨不锁定，连续两次短眨选择第二次时的高亮项。
- 长闭眼 3 秒能退出菜单。
- 长闭眼 8 秒能进入安静模式。
- TTS 中文声音正常。

## 近期不应随意改动

- 摄像头启动流程。
- MediaPipe 初始化和 `detectLoop`。
- EAR 阈值、闭眼时长计算。
- TTS 选声逻辑。
- ROI 相关实验功能。
- 页面主布局。

## 当前清理方向

- `main.js` 保留摄像头、DOM、TTS 和 UI 适配职责。
- 动作解释规则逐步迁移到 `src/shared/aac-input-machine.js`。
- 每迁移一块，就删除或压薄对应旧逻辑。
- 不为减少少量行数引入更复杂的抽象。
